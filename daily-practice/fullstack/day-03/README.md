# Day 3: Assessment review workflow

## Learning objective

Apply integration, persistence, api contracts, verification to the selected behavior.

## Concepts

Enforce submitted reviewed returned transitions; keep feedback history.

## Difficulty

🔴 Advanced.

## Coding exercises

1. Implement enforce submitted reviewed returned transitions using a minimal fixture.
2. Add keep feedback history.
3. Implement an explicit guard or fallback for missing input/content.

## Expected output

Invalid transition rejected. For invalid data, record the specific expected rejection or fallback before running it.

## Challenge problem

Complete the remaining behavior in [Assessment review workflow](../../../mini-projects/fullstack/07-assessment-review-workflow/README.md); introduce a repeated action or boundary value and explain the result.

## Expected learning outcome

Demonstrate and explain the governing rule, with source plus actual evidence. Completion requires observed behavior, not merely time spent.
