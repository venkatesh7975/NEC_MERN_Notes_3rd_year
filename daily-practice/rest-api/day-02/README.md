# Day 2: Patch validation service

## Learning objective

Apply resources, methods, status codes, statelessness to the selected behavior.

## Concepts

Allow title and hours updates only; preserve omitted fields.

## Difficulty

🟡 Intermediate.

## Coding exercises

1. Implement allow title and hours updates only using a minimal fixture.
2. Add preserve omitted fields.
3. Implement an explicit guard or fallback for missing input/content.

## Expected output

Updating title leaves hours unchanged. For invalid data, record the specific expected rejection or fallback before running it.

## Challenge problem

Complete the remaining behavior in [Patch validation service](../../../mini-projects/rest-api/04-patch-validation-service/README.md); introduce a repeated action or boundary value and explain the result.

## Expected learning outcome

Demonstrate and explain the governing rule, with source plus actual evidence. Completion requires observed behavior, not merely time spent.
