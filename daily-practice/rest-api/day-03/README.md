# Day 3: Conditional update lab

## Learning objective

Apply resources, methods, status codes, statelessness to the selected behavior.

## Concepts

Require current revision; reject stale writes with conflict.

## Difficulty

🔴 Advanced.

## Coding exercises

1. Implement require current revision using a minimal fixture.
2. Add reject stale writes with conflict.
3. Implement an explicit guard or fallback for missing input/content.

## Expected output

Two edits at revision 1 allow only the first. For invalid data, record the specific expected rejection or fallback before running it.

## Challenge problem

Complete the remaining behavior in [Conditional update lab](../../../mini-projects/rest-api/07-conditional-update-lab/README.md); introduce a repeated action or boundary value and explain the result.

## Expected learning outcome

Demonstrate and explain the governing rule, with source plus actual evidence. Completion requires observed behavior, not merely time spent.
