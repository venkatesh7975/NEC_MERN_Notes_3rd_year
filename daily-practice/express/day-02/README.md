# Day 2: Request timing middleware

## Learning objective

Apply routing, middleware, static files, errors to the selected behavior.

## Concepts

Assign request IDs; log timing once after finish; exclude sensitive bodies.

## Difficulty

🟡 Intermediate.

## Coding exercises

1. Implement assign request ids using a minimal fixture.
2. Add log timing once after finish.
3. Implement exclude sensitive bodies.

## Expected output

Each request generates one completion record. For invalid data, record the specific expected rejection or fallback before running it.

## Challenge problem

Complete the remaining behavior in [Request timing middleware](../../../mini-projects/express/04-request-timing-middleware/README.md); introduce a repeated action or boundary value and explain the result.

## Expected learning outcome

Demonstrate and explain the governing rule, with source plus actual evidence. Completion requires observed behavior, not merely time spent.
