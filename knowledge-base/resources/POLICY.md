# External resource evaluation and maintenance

Use a publisher reference plus one focused guide for each area. Add an extra article, practice site, or video only when it solves a learning need the existing pair does not. Evaluate authority, technical accuracy, topic fit, level, version, age, and practical value. Free and paid resources must be labeled; a recommendation must not imply paid access is necessary.

The current register was reviewed on 2026-10-08 through publisher pages. This establishes that relevant content was retrieved and reviewed, not that every nested page, snippet, release, or price is verified. Version-sensitive areas explicitly direct learners to their installed runtime and migration guidance. The earlier interview resource catalog retains its recorded partial checks.

Do not invent links or redistribute course text, videos, or paid books. Original repository explanations use references for factual checking, not wholesale copies. A retrieval failure must be recorded and must not be labeled a successful content review. An HTTP 200 from a login page is not evidence that the requested lesson exists.

Videos are supplementary and limited to one to three topical items per area. Verify title, publisher, described scope, and preferably transcript or publisher lesson context. If only metadata can be checked, label that limitation. Do not recommend an older framework tutorial for current setup just because its conceptual explanation remains useful.

The optional `scripts/check-resource-links.mjs` checks HTTP availability and writes a dated report. It does not update content-review dates automatically. Redirects, rate limits, robots restrictions, and transient failures need interpretation. Review the catalog quarterly or after reported breakage; the CI structural gate validates source metadata without making flaky third-party network checks mandatory.
