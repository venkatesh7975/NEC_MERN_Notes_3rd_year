# Living MERN Stack Knowledge Base

This is a connected reference and practice system for beginners, developers, interview candidates, trainers, and engineers. The scope follows the technology landscape, not a fixed set of classroom hours. Start with essentials, build useful behavior, and return to specialized concepts when a real requirement calls for them.

## The 80/20 system

| Priority | Meaning | How to spend time |
| --- | --- | --- |
| 🔥 P0 | Essential / Master | Explain, implement, debug, and demonstrate boundaries repeatedly |
| ⭐ P1 | Highly Important | Apply in a real feature and defend a tradeoff |
| 📚 P2 | Useful | Learn when a project or role needs it |
| 🧩 P3 | Advanced / Specialized | Study after prerequisites and a specific use case |
| 🔬 P4 | Reference / Experimental | Check standards stage and runtime support; do not treat proposals as stable APIs |

These priorities are editorial guidance, not a scientific promise that a fixed percentage guarantees professional readiness. Plan most practical study around P0/P1. Each concept has its own priority even when it shares a guide with specialized concepts.

## How a topic works

Each canonical guide states prerequisites, difficulty, importance, study estimate, mental model, purpose, worked example and runtime, internals, real usage, mistakes, practice, a mini-project, answered interview prompts, related topics, sources, and review date. The concept catalog separately records whether a concept has a direct worked example or only reference depth. A link and a heading do not certify mastery or full API coverage.

Use this loop: read a small part, predict behavior, run or implement it, test a boundary, explain why it works, and record the next weak point. Progress in the browser is local to that browser and can be exported; no account or analytics service is required.
