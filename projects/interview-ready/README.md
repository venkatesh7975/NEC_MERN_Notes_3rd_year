# Runnable interview project source

These implementations complement the original classroom examples and 150 mini-project specifications. They are complete for the documented learning scope; limitations are explicit.

| Source project | Stack | Implemented scope |
| --- | --- | --- |
| [Task board](mern-workspace/README.md) | MERN workspace | Authenticated tasks, status moves, atomic version conflict detection |
| [Reading list](mern-workspace/README.md) | MERN workspace | Authenticated bookmarks, validated HTTP URLs, per-user uniqueness |
| [Expense tracker](mern-workspace/README.md) | MERN workspace | Validated dates and exact amounts, full-account summary, user isolation |
| [Accessible UI lab](ui-lab/README.md) | HTML CSS JavaScript | Accordion, modal, tasks with filter and undo |
| [JavaScript toolkit](js-toolkit/README.md) | JavaScript and Node tests | Debounce, LRU, event emitter, promise pool, two algorithm patterns |

The three MERN apps share one runnable package and security foundation. They are distinct domain applications, not three copied authentication scaffolds. Start with the UI lab, then the toolkit, then the MERN workspace. Extend at least one feature yourself before presenting it as portfolio work.

Use the [project defense worksheet](../../interview-handbook/companies/project-defense.md) to trace your contribution. [Machine coding exercises](../../interview-handbook/machine-coding/README.md) are practice specifications; this index identifies the source that actually exists.
