# Study roadmaps

[Handbook](../README.md)

These are planning estimates. At 10 to 15 hours per week, the full route spans about 12 weeks. If JavaScript is new, extend its phase until the exit checks pass. Spend more time building and retrieving knowledge than collecting courses.

| Week | Focus | Read and practice | Exit check |
| --- | --- | --- | --- |
| 1 | Browser, HTTP, Git, HTML | Web notes; original foundations; semantic registration form | Trace a request and complete the form by keyboard |
| 2 | CSS and accessibility | Layout notes; accordion and modal exercises | Responsive layout at 320px and 200 percent zoom |
| 3 | JavaScript values and functions | Closures, arrays, equality, this; Q011-Q020 | Explain five outputs and implement an immutable update |
| 4 | Async JavaScript and DSA | Debounce, event emitter, LRU, promise pool | Utility tests pass; explain errors and complexity |
| 5 | React state | Forms, reducers, keys, cart and table exercises | Explain each state owner and preserve drafts across errors |
| 6 | React async and machine coding | Search, autocomplete, task conflicts | Latest query wins; complete a timed 75-minute build |
| 7 | Node and Express | Middleware, errors, bounded work, protected CRUD | API rejects invalid and unauthenticated requests |
| 8 | MongoDB and Mongoose | Access patterns, indexes, atomic writes | Prove uniqueness and version conflicts against MongoDB |
| 9 | Security and full-stack integration | Sessions, CSRF, cross-user checks | Two users cannot read or mutate each other's data |
| 10 | Testing and deployment | Route tests, browser checks, production build | Clean install and test report with no unclaimed checks |
| 11 | Design and company preparation | Design notes; selected company playbook; project defense | Explain a notification design and a project failure path |
| 12 | Mock interviews | Two coding mocks, one design mock, one behavioral mock | Record concrete weaknesses and redo one failed exercise |

## Thirty days when you already know the basics

Days 1-5: diagnose knowledge with 20 mixed questions and one timed UI. Revisit JavaScript and CSS gaps. Days 6-10: build the search and table exercises, then review effects, stale closures, and focus. Days 11-15: implement protected CRUD and test two-user isolation. Days 16-20: study indexes, concurrency, and session design; inspect the MERN reference source. Days 21-25: complete two machine coding rounds and a design mock. Days 26-30: rehearse the company playbook, project deep dive, and behavioral stories. Apply throughout; use observed gaps to choose the next practice.

## Seven days before an interview

1. Confirm the format, permitted tools, and role expectations with the recruiter. Do a diagnostic mock.
2. Review JavaScript output tracing, closure, async, and utility implementations.
3. Complete one React machine coding exercise with keyboard and error checks.
4. Review API ownership, sessions, MongoDB indexes, and concurrency.
5. Trace your project end to end and rehearse one design tradeoff.
6. Run a realistic mock; review only the weaknesses it reveals.
7. Check your environment, prepare questions, and use light recall practice. Avoid a last-minute toolchain rewrite.

## Daily session

Use 15 minutes for recall, 45 to 75 minutes for building, 20 minutes for boundary checks, and 10 minutes to record evidence and the next review. Adjust this to available time. Completion means demonstrable understanding, not that a file was opened.
